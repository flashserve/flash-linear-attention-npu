# MegaRecurrentKda 方案设计

方案设计规则版本：V2

## 1. 目标

在 Ascend 950 上，以一次混合 Cube/Vector kernel 调用完成投影、卷积、递推、门控和输出投影。形状与写入范围见[接口](api.md)。主用例为 B40/N8/S4 的 BSH 和 TH，目标为预热后五次完整融合 kernel 耗时的中位数 39.96 µs。实测结论见 [ATK 验收](../../../../../../tests/atk/mega_recurrent_kda/README.md)。

主用例含 160 行，矩阵乘有效工作量约 12.10 GFLOP。在 378.47 TFLOP/s 的 BF16 峰值下，仅 Cube 的数学下界约 31.97 µs。目标假定权重保持热缓存。75,612,160 B 权重若按 1.6 TB/s 从外存重新读取，单次读取已需 47.26 µs。

## 2. Stage 0–2 完整详设

Host 遍历序列的半开行区间 [start,end)。任一区间满足 `start/64 != (end-1)/64`（整数除法）时，整批选择跨块模板 T02，其余选择 T01。这条规则同时适用于 BSH 和 TH。

| Stage | 任务与计算 | 数据所在位置及交接 |
|---|---|---|
| 0 输入投影 | 行主序 X 与行主序权重相乘，逻辑式为 `Y = X @ W.T`。QKV、gate、beta、decay-A 各自投影；decay-B 使用已舍入的 BF16 decay-A。所有投影为 BF16 输入、FP32 累加、BF16 写出。整批少于四行时，decay-A 在 Vector 上沿 K 分组累加后归约 | Cube 经 L1、L0A/B 和 L0C 计算，由 Fixpipe 输出。T01 可在有界 GM 工作区暂存投影。T02 优先用已有工作区容纳多条完整序列。短序列暂存投影。对至少两个 64 行块、且能同时放下两条最长序列的批次，按序列和 head 分核，输入投影经配对 Vector 的 UB 交接，各序列完成递推后由 Cube 直接写出整组的输出投影。其余按 64 行推进 |
| 1 卷积、递推与门控 | 每个序列/head 读取独立 checkpoint。四抽头卷积及 SiLU 后转 BF16，再用 FP32 归一化 Q/K、计算 sigmoid beta 和逐 K 衰减。每步先衰减状态，再计算校正向量、更新状态并生成输出 | Vector 在 UB 中计算，写活动槽的 conv/replay。短序列最多四个 token 时，用 checkpoint 批量得到投影并按 token 次序施加校正。跨块时把块末 FP32 状态交到下一个块 |
| 2 输出投影 | Vector 对递推结果作 RMS 归一化并乘输出门，转 BF16。Cube 执行 `out = gated @ W_out.T`，累加 FP32，Fixpipe 写 BF16 | gated 通过 GM 工作区交接。输出各列独立写入调用方结果 |

Ascend 950 的 MXFP8 路径在 Stage 0 沿 H 每 32 个 BF16 元素生成 E4M3FN 编码和 E8M0 scale。Vector 按连续区间分工，将结果暂存在尚未写出最终输出的 out 中。对可在一个工作区批次内处理、至少 64 行且有多个 head 的 T01，Cube 同时用原始输入计算第一批 head 的 BF16 辅助投影。其余形状在量化后执行这些投影。

量化完成后，Cube 按 128 行、192 个输出列、512 个 K 元素分块，用 NZ 权重和 scale 计算 QKV，并向原有用户 workspace 写入 BF16。同步后，Vector 按序列和 head 执行卷积与递推，Cube 继续其余投影。两批 head 的划分按实际请求数与核数计算，能减少 Vector 调度轮次时才移动一个 head。输出投影先消费第一批结果，读到第二批的起始位置时才等待 Vector。

主用例的有界整批路径将 head 均分为两轮。Q、K、V 和 gate 按输出列分核。T01 整批计算 64–160 行时，若预留四个核后每个其余投影核最多仍需两块 128 列面板，这四个核按行连续完成 decay 的两层投影。每个核读回自己写好的 BF16 中间结果即可启动第二层。其它分工沿用原来的核间同步。第二轮投影与第一轮 Vector 递推重叠。输出投影可先累加已完成的前一组 head，在读取后一组 gated 数据前同步，保持原来的 K 累加次序。按完整序列分组时，递推读完本序列和 head 的 Q 后，复用同一片空间写 gated。按 64 行交接状态时，下一块读卷积历史和 FP32 状态的搬运流水等待上一块写回。

Ascend 950 在序列长度达到 16 时可以把 128 × 128 的 FP32 状态转置到 UB，按输出行并行完成递推。T02 跨块时直接传递该布局。T01 在批内平均长度达到 16 时启用这一实现，批内不足 16 的序列继续用行主序递推。独立编译短序列路径后，Ascend 950 kernel 二进制由 296,136 B 增至 470,152 B。

T02 按完整序列分组时，若 workspace 能容纳 decay-A 和 gated、输出缓冲能容纳按 16 行对齐的投影，且每个波次有足够的独立任务，则临时把投影放在当前分组的输出缓冲。输出投影读到后一组 gated 前，所有 Vector 核已完成对该缓冲的读取。最后一组行数较少时单独核对容量。

用户 workspace 按输入和模板计算。主用例 T01 的 2,012,160 B 包含 40,960 B decay-A 区、327,680 B gated 区和 1,643,520 B 投影区。T02 在 N=8 时为 819,200 B，包含跨块 FP32 状态。ACLNN 查询返回值还计入运行库要求的系统 workspace。

## Atlas A2/A3 实现

公共 Python、Stable ABI 和 ACLNN 接口复用相同的形状校验、模板选择和状态槽映射。
Host tiling 通过 `GetSocVersion()` 识别芯片。A2/A3 使用 `arch22/` 的分核与 workspace 布局，在混合 kernel 内选择 T01 或 T02。Ascend 950 使用 `arch35/`。TilingKey 1 和 3 对应 T01 的短序列与长序列实现，TilingKey 2 对应 T02。
Cube 按 64 行块发布投影。每个 Vector 核按序列和 head 领取递推任务。T01 的序列完整落在一块内，同一核可合并该块多个任务的完成计数。T02 仅在进入下一块时等待该块投影就绪，FP32 递推状态和卷积历史保留在核内 UB。每块的所有任务写完 gated 后，Cube 即可读取对应的输出投影输入。两种模板都按物理槽步长原地写回。

两层 decay 投影由 Cube 使用 BF16 输入、FP32 累加，每层都由 Fixpipe 写出 BF16。
第一层借用本行块的 gated 区，结果就绪后各 Cube 核按列执行第二层。投影权重超过目标芯片 L2 容量时，每次最多对三个 64 行 tile 复用权重。Vector 再以 FP32 计算衰减和递推。CPU 和 Cube 的点积累加顺序可能不同，舍入边界附近的差异会沿投影传播到 replay_decay。
Host 按 token 块数分配投影、门控及同步区。T02 每个序列和 head 只读取一次 checkpoint，用户 workspace 省去 `B × N × 128 × 128 × 4` 字节的跨块状态区。

### Atlas A2/A3 INT8 QKV

Vector 按 token 量化 BF16 输入。Cube 按行块和输出列分工，直接读取 INT8 NZ 权重，写 INT32 累加值。Vector 将结果按通道和 token 反量化到现有 BF16 QKV 缓冲区，再由原有 Stage R 执行卷积。激活编码和 token scale 暂存在最终输出写入前的 `out` 中。当前批次的 QKV 缓冲区尾部和片上 UB 都足以处理全部输出列时，一轮完成 INT32 累加与反量化。尾部不足时，tiling 检查能否把一行的 INT32 累加值分两段存放。前段放在 `out` 的剩余空间，后段借用投影阶段的空闲区域。若辅助投影可能与 INT8 重叠，后段使用 gated 区并避开仍在使用的 decay-A 中间值；能确定辅助投影在 INT8 之后执行时，后段使用尚未写入的 decay 和 gate 投影区。TH 的设备端前缀可能改变模板，Host 对两种调度都预留足够空间。两段容量和 UB 均足够就选择独立的单轮 kernel，否则仍按列分批。只有一个投影块时，Cube 在 Vector 量化期间计算 gate、beta 和 decay-A，在最后一批反量化期间计算 decay-B。最后一次同步同时交付 QKV 和辅助投影。相对同形状的 A2 BF16 路径，额外用户 workspace 为 0 B。

## 跨层复用序列调度

AICPU 顺序读取 TH 前缀，一次扫描生成跨块标志、最长序列和每 16 行的起始序列号。A2/A3 按跨块标志选择递推模板，按每 16 行的序列号计算每个 64 行块应等待的完成数。A5 的 V2 kernel 根据设备调度表选择 T01 或 T02，整序列分组复用最长序列。对于未按 16 行对齐的 token，从表中记录的序列开始，至多在 16 条非空序列内定位。各层仍绑定本层的权重、状态池及槽号。

Ascend 950 Host 根据 shape 返回执行所需的 workspace。TH 中，T≤64 时只需 T01 的空间，T>64 时预留 T01、T02 容量的较大值，使设备选择模板时无需把前缀或结果传回 Host。例如 T=120、N=12 时预留 2,396,160 B。原 T01 同样需要 2,396,160 B，原 T02 为 1,212,416 B。BSH 从等长序列直接确定模板并申请对应大小。69 次串行消费共用一份 metadata，调用方可按 stream 复用临时 workspace。
