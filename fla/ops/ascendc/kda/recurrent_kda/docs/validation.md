# A2/A3 长序列开发验证

基线 e2890ad6。实现已完成，尚未形成 sanitizer 全部零报告的正式验收结论；当前未提交。

## 范围与精度

仅 A2/A3 取消每序列8-token上限，内部窗口仍为8。T<=8快路径保留，长路径 FP32 state 跨窗口驻 UB；
UB、guard、系统 workspace 不变。A5 kernel、入口与 tiling struct 的源码哈希保持不变。
A2/A3/A5单算子构建通过，仅有 A2 硬件实测。
精度：8/8 base、200/200补充、72/72边界、123/123新增长序列均通过；
新增41结构各3固定种子，最长T=1024，原生CPU FP32/FP64双标杆，阈值不放宽。
CPU有限值123配置、18解析对照通过，FP32标杆9代表场景与基线逐元素一致。
运行时实际打开对象与候选构建匹配；安装72对象、API及tiling清单匹配。

## 执行追踪

临时执行追踪版本在40个实际 AIV core 上记录 raw 队列分配、入队、出队、最后读取、释放和窗口边界。
84号 case 的0号核处理 head 0/40/80，共27个窗口；每个有效核确认两个独立 raw slot，
slot 生命周期闭环且无提前复用。108号 case 的0至3号核无有效任务，4至7号核处理长17，
8至11号核处理从17开始的长9；8号核窗口起点实际为17/25，两类用例输出均通过 CPU 比较。
追踪只证明槽位与协议顺序，不作为硬件搬运重叠率的测量。
仅 trace 包申请额外调试 workspace；最终源代码、普通包和性能测试均未保留追踪插桩或额外 workspace。
首版临时追踪曾发生设备异常，已弃用且记录保留；修正后的独立追踪版本验证通过。

## sanitizer

sanitizer 已确认 OPC debug 参数包含 --op_debug_level=1 和 --op_debug_config=dump_cce,sanitizer，
CANN 编译器实际映射至 --cce-enable-sanitizer；对象包含 sanitizer 符号，运行日志确认目标
RecurrentKda kernel 实际 Start 对应工具。普通包、debug 包、trace 包清单分开保存。
racecheck、memcheck：5 个长序列代表、额外有效 varlen 核 2 项、T=17 全核代表、
T=1/T=4 短路径均未报告目标算子错误。93 号补测 block24（起点35、长33），
108 号补测 block8（起点17、长9），避免仅测试空分段所有者。
initcheck：主长序列集 49 条 PRIVATE 报告，两项有效 varlen 各17条；
同一短用例候选与 e2890ad6 均16条 PRIVATE 报告，归一化后调用语句和计数完全一致。
长路径报告的调用语句也已存在于基线，未报告 UB/GM 未初始化读取。
这些证据支持其为既有 API/表达式调用相关报告，但不足以宣称 initcheck 零报告通过。
synccheck：主长序列集740条冗余 set/wait 警告，两项有效 varlen 分别258/78条冗余 set 警告；
同一短用例候选42条、基线44条，未报告缺失同步或死锁。
整体内存验收未记为全部通过。所有原始报告及聚合摘要保留，未通过屏蔽报告或添加大范围同步规避。

普通包已恢复，清单74项匹配，抽查对象没有 sanitizer report 符号，恢复后T9烟测通过。
CANN包编译脚本未修改；仓内临时debug构建参数脚本已原样恢复。
开发验证记录保留，明确整体 sanitizer 零报告验收尚未完成。
