# RecurrentKda 6.0 测试报告

## 1. 测试结论

RecurrentKda 6.0 的 IR、aclnn、tiling、kernel、Python wrapper 和相关测试已完成更新。Ascend 910B 单算子 run 包、Python wheel 及可选 legacy extension wheel 均构建成功，用户指定的三组验收测试全部通过。

## 2. 主要验证范围

- `gate`、`beta` 原生接收 FP32、BF16、FP16；BF16/FP16 在 kernel 内转换为 FP32 参与递推计算。
- `cuSeqlens`、`ssmStateIndicesOptional`、`numAcceptedTokensOptional` 原生接收 INT32、INT64。
- aclnn wrapper 不再对 `gate`、`beta` 和整数元数据执行 `MaybeCast`。
- 支持 BSND 与 TND 输入。
- 支持 raw gate、safe gate、预计算 log gate、beta sigmoid。
- 支持 `initial_state`、`output_final_state`、`inplace_final_state`。
- 支持 V-first 与 K-first 两种 state 布局。
- 支持省略 `cuSeqlens` 的 dense BSND 场景。
- 支持无初始 state 的非原地 final state 场景。

### 4.3 完整算子测试目录（优先级 3）

命令：

```bash
FLA_NPU_RUN_OPERATOR_TESTS=1 FLA_NPU_RUN_LEGACY_TESTS=1 FLA_NPU_RUN_LARGE_SHAPE_TESTS=1 pytest -q tests/operators/recurrent_kda
```

结果：`27 passed, 9 warnings`，无失败、无跳过。

运行前已按 legacy 专用路径要求配置 custom OPP，并在 Python 进程启动前加入其动态库搜索目录；同时显式启用长序列 Kimi shape smoke。最终 27 个用例全部执行并通过。

9 条 warning 包含仓库未注册 `pytest.mark.npu` 的标记警告，以及 legacy API 的预期弃用提示，不影响测试执行与精度结论。

## 5. 最终结论

三个验收层级均达到要求。新增 dtype、可选元数据、state 输出/原地语义和两种 state 布局均已在构建、接口契约及 NPU 精度测试中得到覆盖。
