# Pipelined VDN forward for Ascend 910B

The public entry is `fla_npu.ops.vdn.vdn_forward`. A single mixed AIC/AIV launch runs feature preparation, FP32 Newton–Schulz, the bidirectional scan, bridge and readout. Each scan bank has one writer per head and direction. During a paired-convolution forward, the vector cores prepare the remaining Q frames and form the log prefix while the cube cores scan. The bridge produces panels of 20 frames for 7 heads or 44 frames for 14 heads so readout can consume the preceding panel. Each call owns its workspace.

A device with 20 AICs and 40 AIVs uses a 5 × 4 spatial split across frame groups and channel groups. The 24 AIC / 48 AIV configuration uses 6 × 4. Within each projection, AICs produce the second spatial panel while AIVs unpack and apply the temporal convolution to the first. K defers the last two frames of its first panel for the right halo. V processes an initial eighth of the frames while the remaining spatial results arrive. Once the FP32 keys are ready, Gram A overlaps the remaining V temporal work. Both passes retain the five BF16 taps in their original order. Each AIC owns six 128 × 128 FP32 Newton scratch matrices, and the scan uses the same FP32 summation groups on both configurations.

The qualified range is 64–96 frames and 4–16 heads, with 405 tokens and head dimension 128 (512–2048 total channels). CANN 9.2.1 uses the same per-matrix and per-channel tiling for these shapes. The launcher supplies the actual batch, channel, group and core counts. The no-convolution path computes its beta frame stride from the actual head count. The public dispatcher uses the existing implementation if the reference final frame tile, padded to a power of two, contains fewer matrices than AICs. For these small batches the reference Gram A can use a different FP32 reduction order. The injection GEMM writes its FP32 accumulator to both scan banks before scan begins. This saves one full FP32 tensor of shape (frames, heads, 128, 128). Q/K/V are token-major BF16, beta is contiguous BF16, alpha is contiguous FP32, and bounds are CPU int64. The supported short convolution is the paired K/V path on a 15 by 27 grid. Deterministic execution, disabled HF32, SiLU, Q/K L2 normalization and Newton–Schulz are required. Other configurations use the existing implementation.

The fused path keeps frame-wise workspaces live across stages. On shapes newly admitted to this path, peak allocation can exceed the tiled fallback even with the injection buffer removed. For example, 96 frames and 16 heads with K/V convolution used about 2.49 GiB of incremental NPU allocation on 910B3, compared with about 0.56 GiB for the fallback.

The regular A2 wheel build stages the device library and offline tiling tables when CANN 9.2.1 and the Ascend Triton vector bitcode are present. The host adapter lives in the shared Stable-ABI launcher. It keeps the tensors alive through submission and uses the caller's stream. The device library depends on CANN. Build with the repository's CATLASS headers under `third_party/catlass` (tested revision `3a6b66970ea1469fb566eb5f50afa9a469606e92`).

The feature functions in `device_ir` are LLVM IR generated from the Ascend Triton VDN activations and Newton initialization. `conv_body.hpp` and `gram_body.hpp` contain the device bodies generated by CANN 9.2.1 for the selected convolution and Gram tilings. The spatial convolution uses key 2097177; the FP32 Gram path disables HF32. Regenerate and verify these components before enabling another toolkit version.

Run `VDN_TEST_DEVICE=7 python -m unittest discover -s tests/atk/vdn_forward` against the built wheel to check dispatch, CPU reference agreement, and bitwise equivalence to the existing implementation.

## Device validation

The two-panel implementation was tested on 910B3 (20 AIC / 40 AIV). For 24 AIC / 48 AIV, the host-side checks cover tiling, task ownership, and halo boundaries. Device timing and numerical results for that configuration are pending hardware access.

### Earlier whole-forward baseline

On a 910B3 with CANN 9.2.1, the standard wheel matched the previous PR head (`0c5d2cb8`) bit for bit on 19 accelerated and 27 fallback cases. Each accelerated case was repeated 50 times. Two threads on independent NPU streams also matched their respective references for 50 calls each. These tests used the PR's CPU golden with its existing tolerances.

With paired K/V short convolution, the following numbers cover the complete public call. Each P50 pools 216 synchronized measurements per path across three fresh processes, after warmup and with alternating execution order. Peak memory is the maximum increase in allocated device memory during a call, including its output.

| Frames / heads | Previous PR P50 (ms) | Pipeline P50 (ms) | Previous / pipeline peak (MiB) |
|---|---:|---:|---:|
| 85 / 7 | 9.846 | 5.990 | 383.9 / 1035.8 |
| 87 / 7 | 10.056 | 6.205 | 384.0 / 1054.5 |
| 87 / 14 | 18.854 | 11.871 | 488.5 / 2099.9 |

The full-frame workspace accounts for the higher peak. The largest measured increase over the previous PR path was 1611.4 MiB.
