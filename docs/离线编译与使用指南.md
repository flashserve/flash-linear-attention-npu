# fla-npu 使用与编译指南（在线 / 离线）

本指南面向三类典型场景，说明如何获取、安装、编译和使用 flash-linear-attention-npu 的 Python wheel：

1. **直接使用 wheel 包**（纯使用，免编译）
2. **在线编译 wheel → 离线使用 / 二次离线编译**
3. **离线编译 wheel → 使用**（编译现场完全断网）

> 相关机器代码：`scripts/tools/prepare_offline_bundle.py`、`scripts/tools/extract_offline_bundle.py`，以及 `cmake/third_party/opbase.cmake` 对“无 `.git` 的 opbase 源码”的离线支持。

---

## 1. 产物构成与关键概念

编译产物是一个 **预编译 wheel**，其中包含两部分：

- **预编译算子 OPP**（即装即用，安装后无需再编译）：安装在 `fla_npu/opp/`，通过 ctypes 直调 aclnn/opapi，不绑定特定 `torch_npu` 版本。
- **离线编译 bundle**（可选）：位于 `fla_npu/offline/third_party/`，是从仓库 `third_party/` 缓存提炼出的**最小源码子集**，供开发者离线重编译使用。

离线 bundle 由 `prepare_offline_bundle.py` 在打 wheel 时自动生成；`extract_offline_bundle.py` 能从已安装的 wheel 中把 bundle 还原回源码树的 `third_party/`（CANN_3RD_LIB_PATH）。

### bundle 内容（最小子集策略）

- header-only 库只带 include：`json/include/`、`eigen/Eigen/`、`catlass/include/`
- 需要编译的三方库带必要源码：`opbase/`（剔除 `docs/` 等）、`makeself/`
- abseil / protobuf 走 `ExternalProject`，只带 `pkg/*.tar.gz` **归档**（编译时由 CMake 解压 + patch + 编译）

> 实测（A2 + CANN 9.1.0）：bundle 解压约 **30.7 MB**，压缩进 wheel 增量约 **12.3 MB**。

## 2. 前置环境

三种方式（除纯安装外）都需要先准备 CANN 开发环境与 Python 依赖：

```sh
# 1) 安装 CANN 并激活环境
source /usr/local/Ascend/ascend-toolkit/set_env.sh

# 2) 准备匹配的 conda 环境（Python、torch、torch_npu、torchnpugen、triton-ascend）
conda activate <你的目标环境>   # 替换为你实际的环境名
python -m pip install -r requirements.txt
python scripts/check_npu_env.py --build-only   # 预检，缺依赖会提前报错
```

## 3. 方式一：直接使用 wheel 包（免编译）

适合**纯使用**、包括离线部署的客户。拿到发布 wheel 后直接安装：

```sh
python -m pip install --force-reinstall --no-cache-dir --no-deps \
    /path/to/fla_npu-fla_npu_linux-aarch64.whl
```

- wheel 自带预编译 OPP，运行时**不再编译**，`import fla_npu` 会定位并加载内嵌 `libcust_opapi.so`。
- **注意**：运行时仍需按环境匹配的 `torch` / `torch_npu` / CANN 等；这些不会被打进 wheel。需要同时 `pip` 离线安装的运行时依赖，可用有网的机器 `pip download -r requirements.txt` 到目录，在目标机 `--no-index --find-links` 安装；或直接使用 CANN 官方离线 `.run` 部署包。

---

## 4. 方式二：在线编译 wheel → 离线使用 / 二次离线编译

适合**需要自己编译**、且目标机器可能离网的开发者。

### 4.1 在线编出 wheel（自动内嵌离线 bundle）

在**有网**的机器上，仓库 `third_party/` 缓存完整时，在 `FLA_NPU_BUILD_OFFLINE_BUNDLE=1` 下手动开启内嵌离线 bundle：

```sh
source /usr/local/Ascend/ascend-toolkit/set_env.sh
conda activate <你的目标环境>
FLA_NPU_SOC=ascend950 FLA_NPU_BUILD_OFFLINE_BUNDLE=1 python scripts/build_wheel.py     # 按实际芯片选 ascend910b/910_93/950
```

- `FLA_NPU_BUILD_OFFLINE_BUNDLE` 默认关闭：普通构建（如 CI 仅做功能测试、缓存不完整）不嵌 bundle、直接跳过；只有显式开启且缓存完整时才打包。
- 默认输出到 `dist/`，构建日志会打印本轮 wheel 的准确文件名。
- 若仓库 `third_party/` 缓存**缺失某些必需组件**，离线 bundle 阶段会报错并列出缺项（而不是产出不完整 bundle），请先补齐缓存（见第 6 节）。

### 4.2 离线机直接安装使用

把 4.1 的 wheel 拷到离网站点后，按 **方式一** 安装即用，无需编译。

### 4.3 离线机二次编译（还原 bundle → 断网重编译）

若还需在离线机对源码做**二次编译**，先从已安装的 wheel 还原离线 bundle 到源码树：

```sh
cd /path/to/flash-linear-attention-npu   # 源码树，应含 CMakeLists.txt 与 build.sh
python scripts/tools/extract_offline_bundle.py --src "$PWD"
# 会把 wheel 内 fla_npu/offline/third_party 还原（覆盖）到本地 third_party/
```

随后在**断开网络**的条件下编译：

```sh
source /usr/local/Ascend/ascend-toolkit/set_env.sh
conda activate <你的目标环境>
FLA_NPU_SOC=ascend950 FLA_NPU_BUILD_OFFLINE_BUNDLE=1 python scripts/build_wheel.py
```

- abseil/protobuf 从 `pkg/*.tar.gz` 归档解压编译；json/eigen/catlass/makeself/opbase 本地命中，全程不联网。
- `opbase.cmake` 对无 `.git` 的 opbase 源码直接走离线分支，不再执行 `git checkout`。

## 5. 方式三：离线编译 wheel → 使用

适合**编译现场完全断网**、且没有可参考的在线 wheel 场景。

1. **提前准备一个完整缓存**：把含全部必需组件/归档的 `third_party/` 缓存放到源码树（或 `CANN_3RD_LIB_PATH`），保障布局与 `prepare_offline_bundle.py` 期望一致（源码目录 + `pkg/*.tar.gz` 归档）。
2. 在离线机**断网**下编译并内嵌 bundle：

```sh
source /usr/local/Ascend/ascend-toolkit/set_env.sh
conda activate <你的目标环境>
FLA_NPU_SOC=ascend950 FLA_NPU_BUILD_OFFLINE_BUNDLE=1 python scripts/build_wheel.py
```

3. 按 **方式一** 安装产物 wheel 使用。

> 需要把“已有 bundle”复制成离线缓存时，可用 `prepare_offline_bundle.py` 校验并按需落盘：
>
> ```sh
> python scripts/tools/prepare_offline_bundle.py --cache /path/to/third_party --out /tmp/bundle
> ```

## 6. 离线 bundle 工具与自包含保证

| 工具 | 作用 |
| --- | --- |
| `prepare_offline_bundle.py` | 把 `third_party` 缓存提炼为最小自包含 bundle。**任何必需组件或归档缺失都会以非零退出并列出缺项**，避免产出不完整 bundle 进入 wheel |
| `extract_offline_bundle.py` | 从已安装 wheel 的 `fla_npu/offline/third_party` 还原 bundle 到源码树 `third_party/`，供离线重编译 |

> 只有 `FLA_NPU_BUILD_OFFLINE_BUNDLE=1` 时才会打包 bundle；该开关配合 `third_party/` 缓存使用，缓存不完整时打包阶段以非零退出，避免把缺件 bundle 打进 wheel。

**完整性校验做法**：打好的 wheel 在断网机用 `pip wheel --no-build-isolation --no-deps .` 全链路重编，确认不访问 gitcode/gitee 也能产出新 wheel；若 `prepare` 阶段提示缺件，先补齐对应源码目录或 `pkg/` 归档再继续。

---

## 7. 常见问题

- **报 `cannot build a self-contained offline bundle; missing required ...`**：仓库 `third_party/` 缓存不完整。补齐缺的源码目录或 `pkg/*.tar.gz` 归档后重编。
- **离线机 `import torch_npu` 失败**：先 `source` 对应 CANN 的 `set_env.sh`；torch/torch_npu 与 CANN 版本不匹配时，用匹配版本的环境重建。
- **不需要离线二次编译**：直接走方式一安装即可，无需关心 bundle。
