## 2. 用户行为模拟

| 模拟的用户行为 | 构建/安装动作 | 验证结果 |
|---|---|---|
| 已安装完整 base 后，修改一个已有算子并安装增量包 | base 5 算子；临时把 chunk_local_cumsum host tiling 的 scale 乘 2；生成 1 算子 overlay 并安装 | ctypes/stable 均命中 overlay，sum 20 -> 40 |
| 已安装完整 base 后，只更新一个算子，其他算子继续使用原包 | overlay 只包含 ChunkLocalCumsum；调用 chunk_fwd_o | 非目标算子继续回落 base；parity 2/2 PASS |

| 用户卸载 overlay | python -m fla_npu.install_opp --remove-overlay，新进程再次调用 | base 指纹不变，输出回到基线 |
| 用户提供错误 ABI 的 overlay | 修改 public aclnn 头类型后安装；再手工复制绕过安装器并 import | 安装期和 import 期均硬错误 |
| 用户中断正在进行的构建 | 对构建进程发送 SIGINT，清理整组子进程和半成品后重试 | 没有 .run 半成品；清理后重试成功 |

本轮实际修改的是已有算子 fixture，没有把新算子公共 Python 入口作为 overlay 能力进行验收。

## 3. 构建命令

### 3.1 AOT base 与 overlay

    # base：5 个较快算子
    bash build.sh --pkg --soc=ascend950 \
      --ops=chunk_local_cumsum,chunk_fwd_o,chunk_fwd_h,chunk_scaled_dot_kkt,causal_conv1d -j16

    # overlay：1 个算子

      --ops=chunk_local_cumsum -j16

## 6. 中断与重试

当前实现验证命令：

    timeout --signal=INT --kill-after=10s 8s \
      bash build.sh --pkg --soc=ascend950 --ops=chunk_local_cumsum -j16

验证结果：

1. 顶层 shell 中断后没有产生 .run；
2. 只终止顶层 shell 时，残留子进程会继续操作 build 目录，立即重试可能失败；
3. 新实现通过 process group 终止本地/远程子进程，清理目录后重新执行成功；
4. 全新 worktree 中 -j1 和 -j16 均成功，解包后都是 340 个文件，ops-info、binary-info 和文件集合一致。

进程控制单测：

    python3 -m unittest ci.tests.test_make_packages_process_control -v

Linux 服务器结果为 3/3 PASS。

## 7. JIT 对照

PR 前和当前 PR 都执行：

    bash build.sh --pkg --jit --soc=ascend950 \
      --ops=chunk_local_cumsum -j16

两份 run 包都没有 .o。 在空闲 NPU 7 上手工 staging 后，首次 aclnnChunkLocalCumsumGetWorkspaceSize 均返回 161001。两份 vendor 文件集合只差 README.txt。

因此 JIT 结果记录为既有路径边界：当前 PR 不修改 JIT 行为，也不把 JIT 首调视为 overlay 验收项。当前 wheel staging 的 AOT 产物校验同样不接受无 .o 的 JIT vendor。
