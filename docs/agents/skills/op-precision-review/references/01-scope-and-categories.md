# 检视范围与分类

## 1. 范围

精度静态检视覆盖 transformer / cv / nn / math 四个算子仓。被检视对象可以是：

1. 算子整体实现（`op_host`、`op_kernel`、`op_api`、调用层适配）；
2. PR diff（只看本次改动及其直接影响面）；
3. 已合入代码的回归检视（用历史 issue 集做验收）。

范围之外：性能专项、编码风格、文档校对、CI 配置。这些按其它规范处理，不在本 skill 的检视意见里混报。

## 2. 细粒度根因

类别表示问题的性质，用于定位"改哪里"；级别表示判定所需材料，用于决定"怎么查"和"验收阈值"。

| 细粒度根因 | 定义 | 典型触发 | 需要的材料 |
| --- | --- | --- | --- |
| 同步/事件时序 | 生产者与消费者之间的等待/通知缺失、错配或范围错误 | 缺反向同步、触发流水线设置错误、event 复用未闭环、`PipeBarrier` 跨 pipe 顶替硬事件 | 详设 + 流水/资源报告 |
| 越界/地址偏移 | 读取或写入超出 tensor/UB/L1/workspace 的有效区间 | offset 计算漏乘 stride、tail 未裁剪、workspace 区间重叠 | AscendC API 文档 + 片上资源规格 |
| dtype/format | dtype 或 format 不匹配导致精度/寻址错误 | 中间量按 fp16 累加、bf16 与 fp32 混用、ND/NZ 混用、type 转换点写错 | 接口文档 dtype/format 约束 |
| tiling/分核错误 | 任务切分与数据切分不一致，或多核产出重叠/漏算 | 每核 chunk 数计算错误、余数分配不当、tail 未单独处理 | 详设 + 分核报告 |
| shape/校验缺失 | 不支持的 shape/属性组合未拦截，或被静默执行 | 缺 K/V 档位校验、`cu_seqlens` 单调性未校验、空 tensor 放行 | 接口文档"约束"条目 |
| 模板/分支缺失 | 编译期模板/运行期分支缺少必要实例或走错分支 | 模板实例漏枚举、分支条件写反、dtype 组合落到兜底分支 | 接口文档 + 模板清单 |
| 内存容量/超限 | 片上资源使用超过规格 | UB/L1 驻留超容量、L0A/L0B/C 溢出、workspace 低估 | AscendC API 文档 + 硬件手册 |
| 索引/计数 | 下标、计数、循环边界错误 | 循环上界差一、head/chunk 索引映射错、计数器跨 chunk 未复位 | scalar 数据流 |
| NaN/Inf/除0 | 产生或传播非有限值 | 除 0、`log(0)`、`rsqrt(0)`、除数为累加结果未加 epsilon | scalar 数据流 + 算子语义 |
| 空值/null | 空张量、空可选输入、空指针路径未处理 | 可选输入为空时仍解引用、零长度序列除零、空 workspace 被使用 | scalar 数据流 |
| 数值溢出/位宽 | 超出目标 dtype/整型位宽 | 指数溢出、int32 offset 溢出、累加超 fp16 范围、移位超宽 | scalar 数据流 + dtype 规格 |
| 累加顺序/舍入 | 累加顺序或舍入方式改变导致误差放大 | 部分和顺序不一致、先转 dtype 再累加、归约树与实际不符 | 详设（累加序）；无详设时按 lv3 流程推导 |
| bias/辅助输入 | 辅助输入语义、形状或参与位置错误 | bias 广播方向错、mask 反了、scale 只作用于部分分支、辅助输入截断 | 接口文档 + 硬件/API 用法 |

## 3. 级别划分

| 级别 | 名称 | 判定材料 | 检视难度 | 验收漏警率阈值 |
| --- | --- | --- | --- | --- |
| lv0 | 低级错误类 | 只需明确 scalar 数据流与计算逻辑 | 容易识别 | < 10% |
| lv1 | 功能级错误类 | 算子接口文档的参数说明与"约束"条目 | 需要文档对照 | < 20% |
| lv2 | 指令级错误类 | AscendC API 文档与硬件手册 | 需要片上资源规格 | < 20% |
| lv3 | 方案级错误类 | 算子详设（不易获取），或按流程自行推导 | 依赖全局方案理解 | < 50% |

分级依据：

1. 只看标量与循环逻辑就能判断对错的，一律归 lv0；不要因为"看起来不严重"降级。
2. 判据来自算子接口文档而不是代码本身（"文档说只支持 X，代码没拦"，"文档说必传，代码给了默认行为"）的，归 lv1。
3. 判据来自 AscendC API 约束或硬件片上资源规格的，归 lv2。
4. 判据来自分核方案、内存分配方案、同步协议设计，且必须结合算子详设才能下结论的，归 lv3。

一个 issue 可以同时命中多个类别（例如"尾块越界"既是分核问题也是越界问题）。统计时按主根因记一条，
其余类别记为关联类别，不重复计入问题数。

## 4. 各责任田补充根因

13 类是公共基线。各算子责任田需要补充本领域常见问题点，追加格式：

```text
### <级别> / <细粒度根因>：<本领域的具体问题点>
- 触发场景：<什么输入/配置/分支下发生>
- 代码特征：<在代码里长什么样，最好给文件与行号位置描述>
- 判定材料：<需要读哪份文档/哪段代码>
- 误报边界：<什么看起来像但其实不是>
```

追加内容写在 `02-lv0-lv2-checklist.md` 对应类别下，或 lv3 独立 skill 的同名类别下。不写"注意精度""留意同步"
这类无法落到代码的提醒。
