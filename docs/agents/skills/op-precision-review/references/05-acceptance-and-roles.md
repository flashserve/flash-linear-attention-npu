# 检视验收与分工

## 1. 验收指标

以"各类历史 issue 合入前的代码状态"为测试集，用本 skill 检视，观察能否给出有效意见。指标分两类：

1. **漏警**：issue 对应的核心问题没有被检视意见捕获。漏警是主要指标。
2. **虚警**：人工验收判定"不成立"的意见。虚警只作为准确性与 skill 改进方向的参考。

未被判定为虚警的额外意见计入 **bonus**（额外发现能力），不做扣分。

漏警率定义（按级别分别统计）：

```text
漏警率 = (该级别 issue 问题数 - 检视命中的该级别问题数) / 该级别 issue 问题数
```

验收阈值：

| 问题级别 | 漏警率要求 |
| --- | --- |
| lv0 | < 10% |
| lv1 - lv2 | < 20% |
| lv3 | < 50% |

判定规则：

1. 逐级别判定，不合并计算；某一级别问题数为 0 时该级别记为"不适用"。
2. 命中判定以"issue 的核心问题是否被捕获"为准，不要求文字与 issue 一致：同一处代码、同一根因、
   同一触发条件下给出意见即算命中。
3. 级别按被检视问题在 issue 中的实际级别统计；检视意见的级别与自己不同但命中同一根因时，按命中处理并记录级别偏差。
4. 任一必测级别超过阈值即整体不达标，改进后重跑；虚警率与 bonus 只作为改进方向记录。

## 2. 验收流程

1. 构造数据集：把 issue 拆成条目，每条标注 `level`、`category`、`file`、`line`（或行号范围）、核心问题摘要。
   同一 issue 含多个独立问题时拆成多条，并保证级别归类有依据。
2. 用本 skill 检视对应代码状态（合入前的 commit/分支），输出检视意见；检视者不得提前看到 issue 列表。
3. 人工配对：把检出意见与数据集条目配对（可由检视者显式标注 `hit`，也可按 §3 的规则自动配对后人工确认）。
4. 统计：用 [`../scripts/review_score.py`](../scripts/review_score.py) 计算逐级别漏警率、虚警数和阈值判定。
5. 归因：对漏警条目记录"本应在哪一步发现"（缺材料 / 清单缺该根因 / 级别判错 / 未读到关键代码），
   作为 skill 与责任田清单的改进输入。

脚本用法：

```bash
python3 scripts/review_score.py --issues issues.json --findings findings.json
python3 scripts/review_score.py --issues issues.json --findings findings.json --json > score.json
python3 scripts/review_score.py --issues issues.json --findings findings.json --tolerance 80
```

数据格式与配对规则见 `scripts/review_score.py --help`。脚本退出码 0 表示全部级别达标，1 表示未达标，
便于接入自动化验收。

## 3. 数据集与配对要求

1. 数据集要覆盖被测的算子类别与级别；每个级别至少包含能体现该级别判据的问题（只靠 scalar 逻辑、
   只靠接口文档、只靠 AscendC/硬件规格、只靠分核/同步方案）。
2. 数据集条目的 `file`/`line` 指向问题真正所在的代码位置，不是 issue 描述里的引用位置。
3. 自动配对只用于减少人工工作量：`file` 匹配 + 行号在容差内 + 类别一致视为候选，最终以人工确认结论为准。
4. 检视者的中间产物（算子分析、三份报告）也要纳入审核范围：报告本身的错误同样计为虚警来源。

## 4. 分工

| 级别 | 责任划分 |
| --- | --- |
| lv0 - lv2 | 低错与简单算子：各责任田自行排查，补充本领域根因清单并自查 |
| lv3 | 复杂算子：以领域专家监督为主；复杂算子的 lv3 检视建议按算子类别建立独立 skill 后再执行 |
| 通用 | 公共类别与流程由本 skill 维护；责任田只在对应类别下追加本领域根因 |

责任田需要输出以下四类内容：

1. **触发类别清单**：自身责任田算子的精度/功能问题触发类别（以 [`01-scope-and-categories.md`](01-scope-and-categories.md) §2
   的 13 类为基线，补充本领域类别）。
2. **分级常见问题点**：针对各级别输出常见问题点；lv3 必须具体到环节
   （例如"CV 核间同步缺少必要的反向同步""CV 核间同步的触发流水线设置错误"），不能只写"注意同步"。
3. **算子详细设计文档**：作为 agent 的 reference 提供；没有详设的算子按
   [`03-lv3-whitebox-flow.md`](03-lv3-whitebox-flow.md) ④ 临时生成三份报告并归档，作为后续检视的输入。
4. **中间产物与意见审核**：审核检视 agent 输出的算子分析文档（三份报告）与检视意见的正确性，
   把错报/漏报分别回写到清单与详设。

## 5. 结果记录

验收结果按被测算子类别归档，至少包含：

1. 数据集版本（issue 范围、条数、级别分布）与被检视代码版本。
2. 逐级别问题数、命中数、漏警率、阈值判定。
3. 虚警条目与判定理由；额外发现中被确认有效的条目。
4. 漏警归因与对应的 skill/清单修改记录（改了哪一条、为什么）。
