# 文档正确性与易用性检视 reference

## 1. 文件职责

| 文件 | 唯一职责 |
| --- | --- |
| `README.md` | 功能、输入输出、属性、支持范围、已知限制、Shape 变量附录 |
| `docs/api.md` | Python/aclnn 全部公开入口、参数、返回、布局、返回码、示例 |
| `docs/design.md` | 公式、Stage、分核、内存、同步、模板、验证矩阵 |
| `tests/atk/<op>/README.md` | 输入限制、标杆来源、覆盖矩阵、实际验收结论 |
同一条 Shape 变量只在 README 附录维护；api/design 使用链接，不复制第二份定义。

## 2. 格式

README 至少具备：

- `# <OpName>`；
- `## 功能`；
- `## 输入`；
- `## 输出`；
- `## 属性`（无属性时明确写无）；
- `## 支持范围`；
- `## 已知限制`；
- 可执行示例或示例入口。

API 至少具备：

- Python 主入口；
- 参数和返回；
- aclnn GetWorkspaceSize/Launch 成对说明；
- dtype/shape/layout/format；
- 返回码；
- 示例和调用途径。

设计文档至少具备目标、Stage 职责、数据/workspace、同步、模板/TilingKey 和验证矩阵。

格式不是装饰：同一概念必须使用同一名词，`q_hat`、`qHat`、`qRstd` 不能在不同层无序混用；
代码符号和模型根 README 的符号表必须一致。

## 3. 双向一致性

从文档到代码：

1. 逐条提取“仅支持、不支持、必须、必传、预留、范围、非法”约束；
2. 找到 aclnn/tiling 的实际拦截；
3. 找到对应返回码；
4. 找到负向用例；
5. 检查报错文本是否给出实际值和期望值。

从代码到文档：

1. 列出新增/修改的每个 `OP_LOGE_FOR_*`、`FLA_NPU_DFX_*`、guard；
2. 在 README 或 API 中找到同义约束；
3. 检查 Python/aclnn/稳定入口的支持范围一致；
4. 检查示例传入值没有触发“文档说支持、代码却拦截”的组合。

## 4. 易用性

- 示例能在当前仓库入口直接运行，不依赖未声明的 OPP、wheel、legacy 注册或外部缓存；
- 示例优先使用公共 Python 入口；旧 `torch.ops.npu` 调用必须说明先显式安装 Stable 的 Python 兼容别名，不依赖已删除的 legacy 扩展；
- 默认值、返回 tuple 槽位、可选输出顺序和代码一致；
- 错误场景说明“不支持什么、为什么、当前值、合法范围”；
- 性能/精度命令可复制执行，不泄露内部环境；
- 链接可解析，文件名与目录名稳定；不提交断链、404 和无意义占位符；
- 不在公开文档写服务器、IP、账号、绝对路径、临时目录、日志路径、token 或内部问题单来源。

## 5. 常见问题

- README 支持范围比代码宽，用户合法调用后触发拦截；
- API 返回码写 `ACLNN_ERR_PARAM_INVALID`，代码实际返回内部错误；
- 文档写“预留参数”，代码却读取并参与分支；
- 示例仍是旧入口或旧参数顺序；
- 同一约束在 README/API/ATK README 文案不一致；
- 文档包含本地绝对路径或调试命令；
- 只有成功示例，没有错误示例和返回码解释。
