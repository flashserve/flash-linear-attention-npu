# 标杆生成

本阶段分析用户提供的参考资料和参考实现，并生成或验收独立、可复现的 CPU 标杆，为算子开发和精度测试提供预期结果。CPU 标杆必须实现已确认接口语义，并通过独立 CPU 计算生成预期结果。

## 阶段输入

- [`01-接口确认.md`](01-接口确认.md) 输出的已确认接口契约。
- 用户提供的固定版本参考实现、测试和示例。
- 用户直接提供的可运行 CPU 标杆及其版本、调用说明和已有测试，如适用。
- 用户提供的参考实现运行条件：可用的 GPU 服务器，或能够独立运行参考实现的 Triton Ascend 环境。
- 用户确认的本次支持范围和性能目标。

接口含义不明确或不同材料互相冲突时，在接口确认阶段由用户确认最终解释；CPU 标杆按照确认后的语义实现。

## 分析用户提供的材料和参考实现

从代码、测试和文档中明确以下内容：

- 公式、运算顺序、中间状态和返回值语义。
- 输入输出 shape、dtype、layout、广播、分组和状态参数。
- 累加 dtype、cast 时机、归一化、缩放、数值稳定处理和算法近似。
- fixed/varlen、初始/最终状态、padding、无效区、partial chunk 和空输入行为。
- 可选输入缺失、非法属性、shape 不匹配和其他异常行为。
- 随机性、确定性要求及用户提供的参考实现自身的已知限制。

将分析结果写成“接口语义 → 对应的参考资料或代码位置 → CPU 实现方式”的表格。每个条件分支和常量都要说明它来自哪项接口约定或参考实现。

## 确定 CPU 标杆来源与验收路径

根据用户提供的材料选择一条路径：

1. **用户提供 GPU 服务器**：优先在用户提供的 GPU 服务器上运行固定版本的原始 GPU 参考实现。固定输入、随机种子、dtype、layout、属性和代码版本，保存每个输入及对应输出；CPU 标杆必须读取相同输入并逐个输出对齐。
2. **只有 NPU 服务器**：如果用户提供的 Triton 代码可以通过仓库指导的 Triton Ascend 环境运行，可将它作为参考实现。将 adapter、monkey patch 和其他转发路径配置为独立参考模式，并通过调用路径或运行记录确认实际执行的是 Triton JIT kernel。
3. **用户直接提供 CPU 标杆**：直接使用用户实现作为 CPU 标杆。先确认它可以运行、与接口契约一致、通过纯 CPU 路径独立计算；再运行其已有测试，并补全代表性、边界和异常用例。用户确认该 CPU 标杆是语义和预期结果的依据后，可以直接完成验收。

原始 Triton 代码为适配 Triton Ascend 发生修改时，记录修改内容，并确认公式、计算顺序、输入输出和边界语义与原始版本保持一致。记录参考代码版本、运行依赖版本、输入生成方式和输出文件的对应关系，确保结果可以复现。

当前环境的可用参考材料为用户提供的固定输入和对应预期输出时，使用这组数据完成比较。标杆生成阶段的完成条件是取得至少一种实际运行结果：运行 GPU 或 Triton Ascend 参考实现、比较用户提供的固定输入输出，或者运行并验收用户提供的 CPU 标杆。完成条件达成前，将代码分析和 CPU 实现标记为待验收，并明确记录待补充的运行验证。

既有算子的接口或功能修改按影响范围更新 CPU 语义、预期结果和用例，未受影响部分保持不变。接口契约和 CPU 标杆均保持不变时，继续使用当前 CPU 标杆，并按 `01` 的流程选择结果直接进入 `03`。

## 生成或验收 CPU 标杆

CPU 标杆应满足：

- **独立**：通过纯 CPU 计算路径生成结果，数据和计算过程与目标 NPU kernel 隔离。
- **清晰**：优先使用直接表达公式的 PyTorch CPU 或等价实现，可读性优先于性能。
- **确定**：固定随机种子，明确处理初始化、状态和可选输入；同一输入重复执行结果一致。
- **稳定**：必要时使用更高精度累加或明确的数值稳定算法，再按接口约定转换输出 dtype。
- **完整**：返回值数量、顺序、shape、dtype、layout 和状态语义与接口契约一致。
- **可复用**：CPU 标杆函数可以由单元测试、ATK executor 或其他测试代码直接调用。

CPU 标杆负责生成预期结果和说明计算语义，NPU 算子负责提供实际产品功能。如果参考算法采用近似计算，或者不同计算顺序会产生不同结果，需要记录 CPU 标杆采用的计算顺序、用户提供的参考实现采用的顺序，以及两者的结果差异和比较阈值。

## 对齐用例

先用结果可以人工检查的小规模用例比较用户提供的参考实现和 CPU 标杆，再扩展到更大规模。至少覆盖适用的以下场景：

- 最小合法 shape、常用 shape 和关键维度非对齐的边界 shape。
- fixed length 与 varlen，短序列、tail chunk 和多 chunk。
- head ratio 为 1 和大于 1，关键 K/V/chunk 组合。
- 可选输入存在/缺失、初始状态和最终状态开关。
- padding、无效区、partial chunk、零值、极小值和较大值。
- 支持范围之外组合的预期异常。

对每个输出分别记录比较范围、比较指标和阈值依据。接口没有规定结果的 padding 或无效区只比较有效区域，并在接口契约和测试代码中使用同一套有效区域规则。

## 固化精度基线

CPU 标杆确定后，先按 [`值域校准`](reference/精度对比与定位.md#值域校准) 固化输入值域、生成方式
和混合容差；存在参考实现时，再按 [`标杆对齐`](reference/精度对比与定位.md#标杆对齐)完成比较。
接口没有说明的差异列给用户确认，全部差异解决后才能进入方案设计。

## 阶段输出

进入方案设计前应具备：

1. 用户提供的参考资料和参考实现分析记录，或用户提供 CPU 标杆的验收记录。
2. 独立 CPU 标杆代码及调用说明。
3. 已校准的输入值域、生成方式、最小对齐用例和期望输出。
4. 每个输出的有效区域、比较指标和混合容差。
5. 用户提供的参考实现与 CPU 标杆的对齐结果，或用户提供 CPU 标杆的验收结果。
6. 已知差异、限制和剩余风险。

CPU 标杆完成对齐或验收、值域已校准且所有语义差异解决后，进入 [`03-方案设计.md`](03-方案设计.md)。
