# A5 优化约束

本文记录 A5 上可用于 chunk 间有依赖和无依赖算子的架构能力。通用 resident、4-head window、workspace 和同步原则仍以父目录文档为准。

## 4-Head Window

A5 优化路径默认按 4-head window 规划：

- 每个 bank 4 个逻辑 per-head workspace slot，双 bank 共 8 个。
- per-head direct slot 可以按最小 head-group key共享，但地址和生命周期必须保持到组内最后消费。
- 两个 Vector subblock 交替承包完整 head，非 owner 路径完成协议配平。
- tail 1 至 3 个 head 使用相同 ready/free 模型。
- UB、L1 和 L0 的物理 slot 数由容量与数据通路单独计算，不等同于 8 个 GM 逻辑 slot。

## RegBase 与 VF

连续逐元素依赖可以在 A5 上评估融合为单趟 RegBase/VF：

- 先计算 row/head/chunk 的 base 地址，热循环只保留规则 stride。
- mask、广播 scalar、`Duplicate` 和循环不变量移到循环外。
- BF16/FP16 到 FP32 的 cast 双发使用两套独立输入和输出寄存器链。
- 短 col 循环保留硬件循环，优先展开外层 row；逐列 pair/tail 只在固定基线证明收益时采用。
- 分支专属公式必须在 kernel、golden 和文档中保持一致。
- 同时核算 `RegTensor`、`MaskReg` 和 `AddrReg`，防止寄存器压力反向拖慢。

是否保留以 Task Duration 和完整 AIV pipe 数据为准，不能只看局部 VEC 指标。

## L0C 到 UB

当 AIC 生成矩阵 tile、AIV 紧接消费且 dtype/layout 支持时，可使用 L0C->UB 直连：

- 每条同时在飞的数据边使用独立 UB ping/pong 或证明生命周期不重叠后复用。
- 每个 tile 使用成对 ready/free；AIC 写前等 free，Fixpipe 后发 ready。
- AIV 先搬运与该 tile 无关的 GM 输入，再等待 ready。
- AIV 完成 cast/计算后立即归还 free。
- 没有有效 payload 的 Vector subblock仍按协议 drain。
- 不支持的 dtype/layout 保留 GM workspace fallback。

Host UB 预算按真实 `InitBuffer` 和 API guard 核算，不能只统计有效矩阵字节。

## UB 到 L1

仅供 AIC 消费的 AIV 中间矩阵可以评估 UB->L1 直传：

- 每个并行 head 分配独立 L1 slot；共享输入 head 的结果按复用组只生成一次。
- 直传前确认 ND/NZ 转换、stride 和临时空间的真实实现。
- ready 在 MTE3 写 L1 完成后发出，free 在最后一次 L1->L0 消费完成后归还。
- 共享 L1 slot 保持到组内最后一个 head 消费，下一 window 覆盖前完成 free。
- 不新增无必要的数据边；能复用现有 per-head 协议时仍需重新核算计数。

## L1/L0 驻留

跨 head/group 驻留是通用方法，完整原则见 [`../memory-and-dataflow.md`](../memory-and-dataflow.md)。A5 侧只需额外确认：

- 当前 dtype、tile 和 4-head window 下的实际容量。
- resident operand 与其他 L0A/L0B slot 使用独立生命周期。
- 共享 operand 在组内最后一次 MMAD 后才归还 L0 free。
- 新复用组覆盖前等待旧组完成，不改变每个 head 的公开结果和同步次数。

## 验证

- 对每种 dtype/layout 分支分别确认 direct path 或 GM fallback。
- 覆盖完整 4-head window、tail、同组共享和跨组切换。
- 直连和 resident 修改必须检查 UB/L1/L0 容量、逐 tile ready/free 和最后消费。
- RegBase/VF 修改使用 Release 编译、完整精度矩阵和固定性能基线。
- 对 CV、UB->L1 和扩大生命周期的修改执行流水、race、越界、未初始化和同步检查。
