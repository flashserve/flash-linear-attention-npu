# 项目基础知识

本文提供开发本仓算子所需的稳定基础知识。具体构建命令、当前支持矩阵和交付流程以根目录 `README.md`、`CONTRIBUTING.md` 和仓库规则为准。

## 项目分层

一条典型 Ascend C 调用链如下：

```text
fla_npu Python API
  -> ctypes aclnn wrapper
  -> aclnn L2 op_api
  -> op_host 定义、InferShape 和 Tiling
  -> L0 算子与 op_kernel
  -> NPU
```

- Python API 提供稳定的用户入口、参数适配和必要的 autograd 语义。
- aclnn L2 接口负责公开 C ABI、参数校验、workspace 查询和执行器创建。
- `op_host` 声明输入、输出和属性，完成 shape 推导、TilingKey 选择与 TilingData 生成。
- L0 表达可长期维护的算子内部契约；SOC 和 shape 差异应收敛在同一 L0 内部。
- `op_kernel` 实现 AIC/AIV 计算、搬运、流水与同步。

## 核心术语

- **L2**：面向公开调用方的接口层，包括 aclnn op_api 和稳定 Python API。
- **L0**：L2 下方的算子内部契约。不同 SOC 应复用同一个 L0 定义、原型和调用路径。
- **AIC/Cube**：主要承担矩阵乘、L0 tile 组织和 Fixpipe 输出。
- **AIV/Vector**：主要承担逐元素、归约、类型转换和状态更新。
- **TilingData**：host 根据输入和平台推导后传给 kernel 的运行时参数。
- **TilingKey**：选择编译期模板实例的键，只编码确实影响模板结构的维度。
- **workspace**：公开输出之外的 GM 临时空间；其中的 segment 和 slot 同时构成地址与生命周期协议。
- **resident**：在 UB、L1 或 L0 中跨 tile、stage 或 head 保留并复用的数据。
- **OPP**：算子包中承载 op_api、Tiling、kernel 和配置的运行时产物。

## Shape 与布局

开发前要区分数学 shape、origin shape、view shape 和 storage shape。接口语义使用数学/origin shape；Tiling 和 kernel 可以使用适合硬件的数据布局，但不能把内部 storage 细节泄漏为冗余公开参数。

常见高风险维度包括：

- fixed length 与 varlen 的 token、sequence 和 chunk 映射。
- 一一对应 head 与 grouped/GVA 的 query/key/value head 关系。
- 完整 chunk、尾 chunk、完整 head window 和 tail head。
- ND/NZ、连续与非连续 view，以及 padding lane 是否会被消费。
- 主输入 dtype 与 gate、scale、state 等辅助输入 dtype 不一致的 mixed 场景。

## Chunk 依赖模型

chunk 间无依赖表示不同 chunk 不共享递推 carry，可以把 chunk 作为并行 task 轴。chunk 内仍可能存在 AIC/AIV、stage 和中间张量依赖，不能把“chunk 间无依赖”理解为“整个算子没有同步”。

chunk 间有依赖表示存在类似下面的状态递推：

```text
forward:  S[i + 1] = F(S[i], X[i])
backward: S[i]     = F(S[i + 1], X[i])
```

共享同一份 `S` 的 chunk 必须按依赖方向执行；sequence、batch、head group 或 state tile 等不共享 carry 的轴仍可并行。性能优化前必须先完成这种分类。

## 内存层级和生命周期

GM 容量大但搬运成本高；UB、L1、L0 容量依次受限，但更接近计算 pipe。数据放置由 producer、consumer、复用范围、dtype/layout 和最后消费点共同决定。

每个跨 stage 或跨 pipe 的中间量至少记录：

| 项目 | 需要回答的问题 |
|---|---|
| producer/consumer | 谁生产，谁最后消费 |
| location | GM、workspace、UB、L1 还是 L0 |
| dtype/layout | 使用什么精度和物理布局 |
| ready | 哪条 pipe 完成后可以读取 |
| free | 最后一次消费何时完成 |
| reuse key | 按 chunk、head、head group 还是 tile 复用 |

地址 ping/pong、workspace bank 和事件轮转是不同概念；可以共享索引，但不能混为同一套生命周期。

## 构建产物

- 一体化 wheel 同时交付 Python 包和内嵌 OPP。
- standalone Python 适配 wheel 只提供 Python runtime 和 OPP 骨架。
- run 包用于安装或覆盖特定 SOC 的 OPP 内容。
- 安装后的公开 import 名统一为 `fla_npu`；源码树中的顶层 `fla/` 不是 wheel 的稳定公开入口。
