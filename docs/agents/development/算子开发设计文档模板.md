# 算子开发设计文档模板

本模板用于新增、重构、融合或较大范围优化 Ascend C 算子。具体算子设计文档必须归档到算子目录下的 `docs/算子开发设计.md`，并在实现代码前完成；本模板只作为编写规范，不能替代算子自己的设计文档。

模板结构参考仓内归档的 [GDN backward finalize 全融合 Ascend C 算子设计](../../../fla/ops/ascendc/gdn/chunk_gdn_bwd/chunk_gdn_bwd_finalize/docs/算子开发设计.md)：先固定目标和接口，再说明数学语义、依赖与 stage，之后核算 L1/UB/workspace 生命周期，最后给出 tiling、测试、性能和风险闭环。参考设计中的具体 shape、SOC、stage 编号、窗口数量、slot 数、容量和同步编号都不得直接复制，必须按当前算子重新推导。

## 使用规则

1. 新增算子或大范围融合、重构、性能优化：先复制本模板到算子目录的 `docs/算子开发设计.md`，完成评审字段后再开始实现。
2. 已有算子修改：先更新该算子的设计文档；如果目录中没有设计文档，先补齐再修改实现。
3. 只修改文档、测试或构建配置且不改变算子实现时，可以在 PR 中将设计文档标记为“不适用”，并说明原因和未影响的算子契约。
4. 设计文档中的每个“支持”“不支持”“必传”和“由外部提供”都必须能在代码、接口、测试或构建配置中找到对应证据。
5. 设计发生变化时，先更新设计文档，再更新实现和测试；不能让设计文档长期落后于 kernel、tiling 或公开接口。

## 5. 数据依赖、并行边界与 kernel 形态

先画完整 L2/L0 调用图和 kernel 内 DAG，再决定 stage 或 kernel 边界。每个节点必须标记 chunk 依赖类别：

| 节点 | chunk 依赖 | carry 方向 | producer | consumer | 可并行轴 | 所属 stage/kernel |
|---|---|---|---|---|---|---|
| `<node>` | 无依赖 / 有依赖 | 无 / 正向 / 反向 | `<producer>` | `<consumer>` | `<axis>` | `<stage>` |

- **chunk 间无依赖**：当前 chunk 只依赖原始输入或已就绪的局部数据，可沿 batch、head、chunk 或 tile 并行。
- **chunk 间有依赖**：当前 chunk 消费相邻或更早/更晚 chunk 的状态；必须继续说明 carry 方向、状态 owner、初始状态来源、更新点和同步协议。
- layout、cast、copy 和边界适配也按真实数据边归类，不能仅按代码文件名归类。

若采用单 Kernel 大融合，必须说明：

1. 只有一个 kernel 入口和一套顶层资源、workspace、TPipe 与同步规划。
2. 各 stage 在依赖就绪后执行，不在 kernel 内调用旧 L0 或嵌套启动 kernel。
3. 可复用算法以下沉为无状态内部组件的方式复用；carry 链由明确 owner 维护。
4. 单 Kernel 与多 Kernel 的取舍、容量证据和端到端性能证据。
