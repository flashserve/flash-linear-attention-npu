# Agent Issue 提交规范

本规范适用于 Agent 创建或更新本仓 Issue，包括为 PR 创建关联 Issue。网页、REST API、GraphQL、`gh` CLI、MCP 和其他连接器一律遵守。平台允许创建 Issue，不代表已经满足本仓提交要求。

## 分类和目标分支

每个 Issue 必须按真实用途选择且仅选择一个主分类标签；算子、性能、文档等辅助标签不能替代主分类。

| 用途 | 主分类标签 | 必须使用的模板 | 目标分支标签 |
| --- | --- | --- | --- |
| 功能、精度、构建、兼容性等缺陷 | `bug` | [Bug 反馈](../../.github/ISSUE_TEMPLATE/bug_report.yml) | 至少一个实际需要合入修复的目标分支 |
| 新功能、新算子、能力增强、性能优化等需求 | `enhancement` | [需求建议](../../.github/ISSUE_TEMPLATE/feature_request.yml) | 至少一个实际需要合入实现的目标分支 |
| Committer 晋升申请 | `committer-promotion` | [Committer 晋升申请](../../.github/ISSUE_TEMPLATE/committer_promotion.yml) | 不强制；晋升申请本身没有代码合入目标 |
| 纯使用咨询 | `question` | [问题咨询](../../.github/ISSUE_TEMPLATE/question.yml) | 不强制 |

晋升标签的实际名称是 `committer-promotion`，不得自行写成 `committer` 或中文标签。不得把缺陷或需求标为咨询、晋升来绕过分支要求；咨询中确定需要修复或开发后，应按实际用途更新主分类、模板内容和目标分支标签。

目标分支标签与远端分支同名，例如 `main`、`v26.11.0`；这里指 Issue 的 Labels，不是 Git tag。根据用户已明确的任务范围、关联 PR 的目标分支或已确认的修复计划确定目标。需要合入多个分支时，逐一添加对应标签；发现问题所用的版本、当前检出的工作分支不能自动当作合入目标。目标不明确时保留草稿、说明缺少的依据，不得为通过校验随意默认 `main`。

## 提交前

1. 检查已有公开 Issue，避免重复创建；读取当前仓库对应的 Issue 模板和[仓库规则](../repository-rules.md)。按模板准备中文标题、完整正文和明确的标签清单，API / CLI 提交也必须保留模板栏目。更新时保留与本次任务无关的有效内容和辅助标签。
2. 核对主分类唯一、所需目标分支明确且远端分支真实存在、对应标签存在，并确认当前身份能够写入这些 Issue 标签。缺少标签或写入权限时，先解决该缺项；无法解决则保留草稿，禁止先发布无标签 Issue。不得擅自创建目标分支来满足校验。
3. 公开内容只包含可公开信息，不含账号、服务器、绝对路径、临时路径、凭据或内部问题来源。沿用用户的发布授权与预览要求；需要预览时，展示中文标题、正文以及主分类和目标分支标签清单。

## API / CLI 提交

- REST 创建请求必须显式包含 `labels` 数组，例如已确认目标为 `v26.11.0` 的缺陷使用 `"labels": ["bug", "v26.11.0"]`。
- `gh issue create` 必须显式传入每个 `--label`；不能只在标题或正文中写标签名称，也不能假定 CLI 会自动应用网页模板的标签。
- GraphQL、MCP 或其他工具必须显式传入实际标签或标签 ID。工具不支持标签、权限不足或标签效果无法核验时，改用能够完成全部操作的已授权入口；否则保留草稿，不得省略标签发布。
- 自动补标 workflow 是遗漏后的补救，不能代替 Agent 在请求中带齐标签。

以下示例假设缺陷修复已明确需要合入 `v26.11.0`，标签与分支已核验，且 `issue-body.md` 是按 Bug 模板准备并按要求确认过的完整中文正文；不得照抄版本作为其他任务的默认目标。

```bash
set -euo pipefail

issue_url="$(gh issue create \
  --repo flashserve/flash-linear-attention-npu \
  --title '[Bug]: 已确认的中文缺陷标题' \
  --body-file issue-body.md \
  --label bug \
  --label v26.11.0)"

gh issue view "$issue_url" --json number,url,title,body,labels
```

## 提交后的完成条件

1. 创建或更新后重新读取远端 Issue，不能只检查命令退出码、HTTP 成功状态或返回的 URL。API 的标签请求可能因权限未生效，必须检查读回的实际 `labels`。
2. 核对中文标题和模板正文正常、主分类恰好为预期的一项、Bug / 需求的全部预期目标分支标签均存在，且正文“问题类型”“目标分支”与实际标签一致。晋升和纯咨询分别核对各自的专用分类，不强加分支标签。
3. 标签缺失、冲突或未生效时，修复同一 Issue 并再次读回。不能新建重复 Issue、等待机器人补标或把“已创建但标签未完成”报告成提交成功；无法修复时，明确报告现有 Issue 链接、未完成的标签和阻塞原因，不自动关闭或删除 Issue。
4. 只有读回满足以上条件后，才可报告提交完成，并列出公开 Issue 链接、实际主分类和目标分支标签。更新已存在 Issue 时同样执行这些检查。
