# A5 优化约束

本文记录 A5 上可用于 chunk 间有依赖和无依赖算子的架构能力。通用 resident、head window、workspace 和同步原则仍以父目录文档为准。

## 编码规范

A5 算子先遵守 [`../../development/coding-standard.md`](../../development/coding-standard.md)，再执行本节专项约束。这里规定代码组织和生命周期表达，不固化具体算子的 shape、tile、slot 数或公式。

### 文件与入口

- A5 专项实现放在 `op_kernel/arch35/`，文件名与通用路径保持同构；不要把 A5 分支散落到通用 Cube/Vector 热循环。
- 统一 kernel 入口只在 include 和模板实例化层选择架构实现，AIC/AIV 分别构造对应类并调用 `Init()`、`Process()`。
- `*_struct.h` 只维护 host/kernel 共用 tiling ABI 和模板组合；`*_common.h` 只放协议常量、任务信息结构和无状态 helper。
- Cube 与 Vector 分文件维护，禁止通过一个巨型类同时管理两侧资源和同步状态。
- A5 与其他 SOC 继续复用同一个 L0 原型、注册和 L2 调用路径，平台差异不得泄漏为第二套公开或私有 L0。

### 模板与热路径

- dtype、固定维度和会改变内部指令结构的模式使用模板参数表达，并在 host 侧显式枚举支持组合。
- 模板内部使用 `if constexpr` 裁剪无效路径；禁止在最内层循环重复判断 dtype、SOC 或可编译期确定的功能模式。
- RegBase/VF helper 使用 `__simd_vf__ inline`，一个 helper 只完成一种 cast、填充或逐元素公式。
- mask、广播 scalar、循环不变量和寄存器声明尽量移出热循环；尾部必须使用有效元素 mask，不能默认整向量有效。
- 成对寄存器链、循环展开和硬件循环只在资源预算与性能数据支持时保留，不能把某次实现的展开因子升级为全仓常量。

### Cube 资源表达

- 优先使用既有 Catlass/TLA 的 layout、tensor、tile copy 和 MMAD 抽象表达 GM/L1/L0 数据通路，避免重复手写等价地址变换。
- L1、L0A、L0B、L0C 的 buffer 数、tile bytes、offset 和 event ID 使用 `static constexpr` 集中定义。
- 对可静态推导的 L1/L0C 总量执行 `static_assert`；双缓冲放不下时由编译期容量判断降为单缓冲，不在运行时猜测。
- resident 与 scratch 使用不同命名和事件；复用 operand 的 cache key、有效位、slot 和最后消费者必须显式记录。
- MMAD helper 明确 first/last reduction tile，只有最后一个归约 tile 发布 Fixpipe ready，并在最后消费后归还 L1/L0 slot。

### Vector 资源表达

- `Init()` 负责绑定 GlobalTensor、缓存 tiling 字段、初始化 TBuf/LocalTensor，并分配 event；`Process()` 只编排 task/window/chunk/head 和 stage。
- input、gate、state、output 和 CV direct buffer 使用独立 ping/pong 索引和命名 event 数组，不得因底层地址暂时相同而混用生命周期。
- event 名称应表达 `producer pipe -> consumer pipe + resource`，复制 helper 必须在覆盖前 wait、搬运后 set，并返回或接收实际 slot。
- 所有手工分配的 event 在退出前先 drain 再 release；可选输出、空任务和 tail 分支不得绕过回收路径。
- 两个 Vector subblock 按完整 head 分配 owner；非 owner 即使没有 payload，也必须完成该 head 所需的跨核协议配平。

### Tiling 与边界

- host tiling 的主流程按 `PreCheck -> CommonTiling -> Variable/Fixed -> WorkspaceTiling` 分层，每一步失败立即记录公开参数语义并返回。
- required/optional、维数、dtype 组合、互斥输入、范围和 head 关系必须在 host 拦截；kernel 不承担本可前置的合法性判断。
- workspace 按命名 segment 顺序计算 offset，每段按真实 dtype 和搬运要求对齐；逻辑 workspace slot 与 UB/L1/L0 物理 buffer 分开计数。
- kernel offset 使用 `int64_t` 或足够宽的无符号类型；窄化到 API 参数前显式检查或转换。
- fixed/varlen 共用 seq/chunk helper，主循环只消费 `valid`、token 起点、有效长度和输出下标，不复制两套数据流。

### 同步可审查性

- 核内 event ID 和跨核 flag 编号集中定义并通过命名 helper 取 slot 对应事件；热循环不得散布无法追踪的裸编号。
- 初始化函数建立每个 slot 的初始 free 状态，收尾函数等待所有在飞事件并恢复协议；初始化和收尾必须能够逐项对应。
- 每条跨 AIC/AIV 边明确 producer、consumer、ready/free、pipe、slot 和计数；CV 双缓冲还需区分 subblock flag 空间。
- `PipeBarrier` 只用于已确认的同 pipe RAW/WAR/WAW，不能代替跨 pipe event，也不能作为 kernel 末尾的习惯性同步。
- direct path 与 GM fallback 可以使用不同数据通路，但必须保持相同 stage 边界、公开语义和 owner/non-owner flag 次数。

## Head Window 选择

A5 不固定使用 4-head window。先测量归一到单 head 的 Cube 服务时间 `T_C`、单个 Vector subblock 服务时间 `T_V` 和有效 owner 数 `N_V`，再结合完整 timeline 选择最小有效窗口：

- 两个 Vector subblock 交替承包完整 head 时，先评估 2-head；如果两个 subblock 不是独立 owner，则直接按实际消费间隔判断。
- 当 Cube 没有明显快于聚合 Vector，或 2-head 已无明显空洞时，不采用 4-head。
- 只有 `T_C` 明显小于实际聚合 Vector 消费间隔，且 2-head 中的空洞、背压或排空间隔能被额外在飞 head 隐藏时，才保留 4-head。
- 跨 head/group 驻留可独立支持更大窗口，但必须单独证明容量、生命周期和 Task Duration 收益。
- 每个 bank 使用 `windowSize` 个逻辑 per-head workspace slot，双 bank 共 `2 * windowSize` 个。
- per-head direct slot 可以按最小 head-group key共享，但地址和生命周期必须保持到组内最后消费。
- 两个 Vector subblock 交替承包完整 head，非 owner 路径完成协议配平。
- 不足 `windowSize` 的 tail 使用相同 ready/free 模型。
- UB、L1 和 L0 的物理 slot 数由容量与数据通路单独计算，不等同于 GM 逻辑 slot 数。

## RegBase 与 VF

连续逐元素依赖可以在 A5 上评估融合为单趟 RegBase/VF：

- 先计算 row/head/chunk 的 base 地址，热循环只保留规则 stride。
- mask、广播 scalar、`Duplicate` 和循环不变量移到循环外。
- BF16/FP16 到 FP32 的 cast 双发使用两套独立输入和输出寄存器链。
- 短 col 循环保留硬件循环，优先展开外层 row；逐列 pair/tail 只在固定基线证明收益时采用。
- 分支专属公式必须在 kernel、golden 和文档中保持一致。
- 同时核算 `RegTensor`、`MaskReg` 和 `AddrReg`，防止寄存器压力反向拖慢。

是否保留以 Task Duration 和完整 AIV pipe 数据为准，不能只看局部 VEC 指标。

## L0C 到 UB

当 AIC 生成矩阵 tile、AIV 紧接消费且 dtype/layout 支持时，可使用 L0C->UB 直连：

- 每条同时在飞的数据边使用独立 UB ping/pong 或证明生命周期不重叠后复用。
- 每个 tile 使用成对 ready/free；AIC 写前等 free，Fixpipe 后发 ready。
- AIV 先搬运与该 tile 无关的 GM 输入，再等待 ready。
- AIV 完成 cast/计算后立即归还 free。
- 没有有效 payload 的 Vector subblock仍按协议 drain。
- 不支持的 dtype/layout 保留 GM workspace fallback。

Host UB 预算按真实 `InitBuffer` 和 API guard 核算，不能只统计有效矩阵字节。

## UB 到 L1

仅供 AIC 消费的 AIV 中间矩阵可以评估 UB->L1 直传：

- 每个并行 head 分配独立 L1 slot；共享输入 head 的结果按复用组只生成一次。
- 直传前确认 ND/NZ 转换、stride 和临时空间的真实实现。
- ready 在 MTE3 写 L1 完成后发出，free 在最后一次 L1->L0 消费完成后归还。
- 共享 L1 slot 保持到组内最后一个 head 消费，下一 window 覆盖前完成 free。
- 不新增无必要的数据边；能复用现有 per-head 协议时仍需重新核算计数。

## L1/L0 驻留

跨 head/group 驻留是通用方法，完整原则见 [`../techniques/memory-and-dataflow.md`](../techniques/memory-and-dataflow.md)。A5 侧只需额外确认：

- 当前 dtype、tile 和所选 head window 下的实际容量。
- resident operand 与其他 L0A/L0B slot 使用独立生命周期。
- 共享 operand 在组内最后一次 MMAD 后才归还 L0 free。
- 新复用组覆盖前等待旧组完成，不改变每个 head 的公开结果和同步次数。

## 验证

- 对每种 dtype/layout 分支分别确认 direct path 或 GM fallback。
- 覆盖所选完整 head window、tail、同组共享和跨组切换。
- 直连和 resident 修改必须检查 UB/L1/L0 容量、逐 tile ready/free 和最后消费。
- RegBase/VF 修改使用 Release 编译、完整精度矩阵和固定性能基线。
- 对 CV、UB->L1 和扩大生命周期的修改执行流水、race、越界、未初始化和同步检查。
- 检查 A5 文件分层、模板组合、资源 `static_assert`、event 初始化/回收和 owner/non-owner 协议均满足本页编码规范。
