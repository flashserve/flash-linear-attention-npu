# A2/A3 优化约束

本文只记录通用优化方法在 A2/A3 上落地时需要额外确认的架构约束。依赖模型、head window、resident 和同步原则以父目录文档为准。

## 资源预算

- L1、L0 和 UB 使用量按目标 SOC 编译配置和实际 API 临时空间核算。
- 已有实现常以 512 KiB L1 和 16 KiB 级单次 Vector matrix copy 作为规划边界；迁移到新 kernel 前必须根据当前平台、CANN 和真实 `InitBuffer` 重新确认，不能直接复制数字。
- resident、L1A/L1B scratch、L0A/L0B、L0C、所选 head-window per-head slot 和 API guard 全部进入预算。
- resident 与 scratch 地址和事件独立；不能借用 scratch 后延长生命周期。

## AIC 流水

- L1A 和 L1B 分别使用独立 scratch ping/pong 和事件。
- L0A/L0B 优先使用双缓冲，让 MTE1 与 MMAD 重叠。
- L0C 是否双缓冲由单 tile 占用和 Fixpipe 生命周期决定；容量只够一个结果时保持单槽。
- 归约维分块时累加到同一 L0C，仅在末块完成后执行一次 Fixpipe。
- L1/L0 跨 head/group 驻留遵循通用最后消费原则，不因平台名称改变所有权。

## AIV 流水

- matrix input、small-tensor input、output 和 state 使用独立或经过证明的 slot 生命周期。
- row tile 先扣除 resident、双缓冲和临时空间，再按对齐逐级缩小。
- 类型转换和 DataCopy 解耦，避免一个 helper 隐式占用多个 ping/pong。
- 完整 row 使用主路径，尾 row 使用独立有效长度和 mask。

## Head Window 调整

部分早期 A2/A3 实现以 2-head window 和有限 raw flag 积压深度设计。先按通用服务时间模型确认是否需要扩大窗口；两个 Vector subblock 各自承包完整 head 且 2-head 已稳定重叠时，不需要改成 4-head。

profiling 证明应扩大窗口时必须重新设计：

1. 两个 bank、每 bank `windowSize` 个逻辑 per-head workspace slot，共 `2 * windowSize` 个。
2. 最大在飞数据边和同一方向未消费 ready 数。
3. 每个 `bank/headOffset/data-edge` 的 ready/free 或等价 credit。
4. 两个 Vector subblock 在完整窗口和尾窗口下的配平。
5. 跨窗口预取时上一 bank 的最后消费和反向 free。

不得把只证明可积压 2 次的 raw flag 直接用于更深的 producer 领先。无法建立可靠背压时，保留 GM fallback，并说明窗口选择证据。

## 数据通路

- 默认中间量落 GM workspace，直连能力必须以当前 A2/A3 公共 API 和实际编译结果为依据。
- consumer-friendly 的物理转置或 NZ 布局可以减少 Vector 散写，但需要同步更新 workspace 语义和精度 reference。
- 缓存公共中间量时按最小 head-group key，跨 bank 复用前证明上一窗口已完成最后消费。

## 验证

- A2 和 A3 至少完成目标 SOC 编译；共享路径修改按风险执行运行验证。
- 覆盖所选完整 head window、尾窗口和多个连续 window。
- 使用流水数据确认 MTE2/MTE1/M/Fixpipe 与 AIV 搬运/计算存在预期重叠。
- 对扩大 flag 深度、slot 数或 resident 生命周期的修改执行同步、race、越界和未初始化检查。
