# Chunk 间无依赖算子

本文适用于不同 chunk 之间没有递推 carry 的算子。chunk 内部仍然可能存在多阶段 AIC/AIV 数据依赖和同步。

## 语义判定

满足以下条件时，chunk 可以作为独立 task：

- 当前 chunk 的输出不读取前一或后一 chunk 更新后的状态。
- 跨 chunk 共享输入只读，不形成写后读或读后写依赖。
- 跨 head/group 的累加关系有明确 owner，不依赖其他 core 的隐式执行顺序。
- varlen offset 和输出下标可以从当前 sequence/chunk 信息独立推导。

如果存在跨 chunk carry、累积状态或输出回读，转到 [`分块间有依赖算子.md`](分块间有依赖算子.md)。不要通过全局 flag 强行把本可并行的 chunk 串行化。

## Task 划分

优先按以下轴增加并行度：

1. batch 或 sequence。
2. chunk。
3. 不共享输出或归约状态的 head/head group。
4. 可独立写回的 value/state tile。

一个 task 应拥有完整的 chunk 内计算和写回责任。若多个 value head 会累加到同一个 key head 输出，必须选择以下一种显式方案：

- 同一 core 顺序处理同组 head，首项覆盖、后续项累加。
- 不同 core 写独立 partial，随后执行独立规约阶段。
- 使用满足 dtype、顺序和性能要求的原子累加。

不能让多个 core 无协议地读改写同一输出。

## Head Window

每个 task 内按已验证的 `windowSize` 组成逻辑窗口：

```text
for task in core_tasks:
    for headBase in range(0, headCount, windowSize):
        activeHeads = min(windowSize, headCount - headBase)
        bank = windowIndex & 1
        run all active heads of stage 0
        run all active heads of stage 1
        ...
        retire the window
```

- head window 只组织 chunk 内 stage，不改变 chunk 之间的独立性。
- 共享只读输入或公共中间量时，按最小依赖键在窗口内生成一次并复用。
- tail head 保持与完整窗口相同的数据边和同步协议，只缩小有效 payload。
- 两个 bank 轮转时使用 `2 * windowSize` 个逻辑 per-head workspace slot；UB/L1/L0 buffer 另行规划。

## Stage 与同步

先为当前 chunk 画 producer-consumer DAG，再按真实跨 pipe 数据边划分 stage。stage 0 中只依赖原始输入的 AIC/AIV 工作可以并行；wait 放在下一 stage 第一次消费对端产物之前。

无 chunk carry 不意味着可以省略：

- AIC/AIV 之间的 ready/free。
- L1/L0/UB slot 的核内事件。
- 同一输出归约组的 owner 和写回顺序。
- window bank 覆盖前的最后消费确认。

## 验证重点

- 同一个 core 连续处理多个 task，触发 workspace bank 复用。
- head 数覆盖 1、2、所选完整窗口、尾窗口以及大于一个完整窗口的场景。
- grouped/GVA 覆盖同组复用和跨组切换。
- chunk 数大于 core 数时验证 task 轮转和输出下标。
- fixed/varlen、尾 chunk 和空 sequence 不产生跨 task 串扰。
