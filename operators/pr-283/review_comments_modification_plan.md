## 待修改项建议落地顺序

1. **先修兼容回退**
   - 修改 `chunk_scaled_dot_kkt_tiling.cpp`，950 上 `!useCatlassScore` 不直接 `GRAPH_FAILED`。
   - 同步确认 `chunk_scaled_dot_kkt.cpp` 在 A5 非 Catlass 情况能执行 matmul fallback；当前 A5 宏分支 `!UseCatlassScore()` 会直接 return，不能只改 host。

2. **BT=64 整块 Catlass score + A5 RegBase epilogue**
   - `ScoreRowBlockSize()` 对 BT=64/A5 返回 64。
   - host `ScoreRowBlockSize(bt)` 与 kernel `ScoreRowBlockSize()` 保持一致。
   - 确认 `scoreTileBuf_`/`outTileBuf_` 分配足够 `64*btAlign`。
   - 让 `CanUseA5RegBaseEpilogue(rowBegin,rowCount,colCount)` 在 BT=64 下命中，调用 `ProcessKktEpilogue64VF`。

3. **加深或重构 AIC/AIV score 流水**
   - 短期: `SCORE_WORKSPACE_BUFFER_NUM` 从 3 调到 4/6，扩展 ready/done flag。
   - 中期: 参考 KDA direct-score 思路，设计 AIC UB -> AIV UB 直传，减少 GM workspace 写读往返。
   - 最新意见补充: 不能只加深 slot；需要把 CV stage 从 scoreGroup 级同步改为 tile/window 级同步，并让 slot 与 `(chunk,hv)` 有稳定映射。

4. **BlockMmad 复用**
   - 将 `Resource`/`BlockMmad` 提到 score group 循环外。
   - 一次 `preSetFlags/finalWaitFlags` 区间内连续下发多个 score block。
   - 这项建议在 BT=64 整块路径后复测再决定是否立即做，避免一次改太多变量无法归因。

5. **AIV epilogue 双缓冲与 g/beta 缓存**
   - g/beta 由每 row block 重复读改为每 chunk/head 读一次。
   - 按 `(b,hv,chunk)` 建 resident 缓存，row block/stage 复用 resident slot。
   - `gQueue_`/`betaQueue_`、score/out local buffer 做 ping-pong。
   - 将 `WaitMte2ToV` 从 row/tile 内循环移到消费者 stage 入口。
   - 若 GVA `hvPerHk` 仍拖慢，拆成更多 AIV epilogue head task。

6. **Cumsum fp16/bf16 fast path**
   - 先核对当前 CANN `CumSum` 是否支持 half/bfloat16。
   - 支持则直接扩展 dtype；不支持则实现 cast 到 fp32 的 fast path，同时重算 UB buffer。
