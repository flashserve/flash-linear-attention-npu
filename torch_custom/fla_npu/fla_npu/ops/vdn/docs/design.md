# 实现与性能

## 执行阶段

| 阶段 | 数据依赖 | 实现 |
| --- | --- | --- |
| 逐帧生成因子 | K、V、β 和 α → transition、injection | 每个帧块内计算 value Gram 和 FP32 key Gram，获得 X=M⁻¹ 后写出 T=diag(α)X 和 U=BX。各头独立，尾块只写回有效帧。 |
| 双向状态递推 | 全部 T、U 与两端文本初态 → 两个 FP32 状态库 | 正向或反向逐帧做 state @ T + U。910B 优化内核按头和方向分配链，每条链保持帧序。 |
| 计算窗口衰减 | α → F+1 个对数前缀 | 每列取 log 后沿帧维累加。窗口两端用前缀差取 exp，避免反复计算区间乘积。 |
| 合并及读出 | 左右边界状态、对数前缀、Q → 输出 | 逐块加载窗口外沿的两个状态，分别按列衰减后相加。状态舍入到 Q 的 dtype 后做矩阵乘，最后一块丢弃补齐输出。 |

两个求解器处理相同的对称正定系统。`vdn_solve` 按 32 行做 Cholesky 面板分解，再合并下三角逆。
Newton 路径以 `c=2/407`、`X₁=2cI−c²M` 开始，继续 11 次 `X ← X(2I−MX)`。
优化路径保存 −M，使用两块逆矩阵缓冲交替写回，并在校正矩阵的对角区域加 2I。
只有 FP32 且匹配分块条件的路径才选择原生 Newton 校正。关闭 HF32 时，A2 原生递推对每个头的每个方向使用独立的状态序列。

两个 FP32 因子张量合计占 `8FHD²` 字节。两份包含文本边界的状态库合计占 `8(F+1)HD²` 字节。
在 F=87、H=7、D=128 时分别为 76.125 和 77 MiB；Gram、求逆缓冲、输出及分配器还会影响实测峰值。主块采用 64 帧时，剩余 23 帧可以补至 32；补齐槽不会进入扫描。

## 复现条件

使用同一设备、相同输入步长、相同 `frame_tile` 和特征开关分别比较各求解器。典型 TP8 配置为 87 帧、7 个可见头、每帧 405 token、D=128、BF16 特征、FP32 Gram 与求逆、预计算文本状态。开启 SiLU 和 Q/K L2Norm，关闭短卷积和 HF32。计时不包含 TP 通信。先对全 clip 的结果进行精度检查，再预热并采集至少 31 次同步前向，记录 P10、P50、P90 及增量峰值显存。单算子新增显存按基于输入就绪时已分配字节的增量计算；reserved memory 另报。

原型在该配置上的同步 P50 为 4.209 ms，P10–P90 为 4.128–4.299 ms。原型同一次设备 profile 中，生成因子、状态扫描、衰减前缀和合并读出的执行时间分别为 2.880、0.394、0.069 和 0.446 ms。独立 trace 的插桩开销、阶段间空隙及主机提交均会影响首尾跨度。PR 版本的入口、环境与实测结果见[测试说明](../../../../../../tests/atk/vdn_forward/README.md)。
