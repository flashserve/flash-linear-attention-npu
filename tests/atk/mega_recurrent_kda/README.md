# MegaRecurrentKda ATK

安装对应产品的 wheel 后从仓库根目录运行。A2 使用 `ascend910b`，A3 使用 `ascend910_93`，Ascend 950 使用 `ascend950`。

```bash
bash tests/atk/run_test_cpu.sh -op=mega_recurrent_kda -soc=ascend950 -npu_device_id=0 -scope=accuracy
```

开发时，CPU 标杆的五项输出默认缓存在仓库的 `build/cpu-golden-cache`，可通过 `FLA_KDA_GOLDEN_CACHE` 指定复用目录。输入张量内容、布局、标量、标杆源码或 CPU 计算配置变化时重新计算。每次验证仍执行当前设备实现并比较输出。

九个用例覆盖 BSH、TH、不等长序列跨越 64 行、卷积权重的三种布局、物理状态槽间隙、缓冲区复用及 4096 token。CPU 与设备由相同种子生成输入，CPU 执行独立的 PyTorch 参考。设备调用公开 Stable ABI，检查四个状态输出与输入共用地址，以及 checkpoint 保持原值。

精度边界回归可另行运行 `python -m pytest -q tests/atk/mega_recurrent_kda/test_precision_boundaries.py`。用例覆盖单行 decay 投影、跨块卷积历史交接，整批 66 行但末组仅余 3 行时的 decay 计算，变长序列在非对齐位置切换分组、投影借用输出后的单行尾部，以及同一批次中长短序列共存的情况。

| 文件与分支 | case ID | 覆盖 |
|---|---|---|
| 精度，T01 | 0、1、4、5、6、7 | 单 token、不等长短序列、状态槽间隙、两种主布局、五个 64 行块 |
| 精度，T02 | 2、3、8 | 不等长序列跨界、129 token、多次状态交接至 4096 token |
| 性能 | 5、6 | B40/N8/S4，分别为 BSH、TH |
| 确定性及内存 | 0、4 为 TilingKey 1，2 为 TilingKey 2 | 基本路径、带槽间隙路径和跨块路径 |

在 Ascend 950、CANN 9.2.0-beta.2 上用相同的 CPU 标杆执行完整 ATK。精度 9/9、确定性 3/3、内存检查 3/3 均通过。两项性能任务成功采集数据。另通过公开 Python 入口逐项验证 out、conv_state 和三项 replay，重复运行结果一致，checkpoint 和未写区域保持原值。非法参数覆盖见 [10 个反例](test_invalid_inputs.py)。

B40/N8/S4 的交付构建预热 3 次，随后 5 次融合 kernel 的 Task Duration 中位数为 BSH 99.946 µs、TH 97.624 µs；同批形状在另一比较构建上为 94.160/93.781 µs。目标均为 39.96 µs，两项均未达标。CPU 计时覆盖 Python 调用至设备同步完成，交付构建测得 BSH 186.170 µs、TH 270.777 µs。这个口径包含元数据传输、分发和同步。

Ascend 950 的当前版本通过 810 个 B/N/S 与布局组合、36 项换种子复验、5 项变长分组复验。下表为同卡交错测量的融合 kernel 耗时。分别对基线及本版测三轮，每轮预热 3 次，取后续 5 次的中位数，再取三轮中位数。基线为本次长序列调度改动之前的版本。

| B/N/S | BSH 基线 → 本版（µs） | TH 基线 → 本版（µs） |
|---|---:|---:|
| 40/8/4 | 90.371 → 88.750 | 91.174 → 89.887 |
| 40/8/31 | 2,416.948 → 1,524.575 | 2,425.316 → 1,533.014 |
| 40/8/32 | 1,513.022 → 1,394.095 | 1,522.104 → 1,403.501 |

另用 msSanitizer 检查两个变长用例。长短混合的 T01 用例通过。T02 在 256 行后剩 1 行的用例触发 10,099 条多核写入告警，其中 10,054 条位于输出、45 条位于 workspace，均在申请范围内。强制递推和最终输出串行后数量相同；诊断版省去最终输出写入后余 45 条，再省去下一组对 workspace 的复用后归零。每块分配前后 64 KiB 保护区均完好，racecheck 未报告错误。两个用例各测三个种子，每个种子运行 64 次，五项输出均可重复。

独立的 26 项复测中，B40/N8/S4 为 BSH 89.928 µs、TH 90.546 µs。短序列的改变量较小，个别形状最多慢约 1.2%。主用例的 39.96 µs 目标仍未达到。

Atlas A2 与 A5 使用相同的 810 个用例 ID、CPU 标杆、种子和精度阈值。其中 672 项来自 3 个 B、8 个 N、14 个 S 的全部组合，每组分别测试 BSH 和 TH。其余 138 项覆盖长序列、变长序列和形状边界。A2 此前单独执行的 163 项中有 112 项与这套清单重合，两轮合计覆盖 861 个不同用例。

A2 在共同清单上有 767 项的五个输出全部通过原精度阈值。另有 41 项仅 `replay_decay` 超差，使用设备两级投影写回的 BF16 值按标杆公式继续计算，最大绝对差降至 1.20×10⁻⁷。另两项是 B=2、N=1、S=3 的两种布局，`replay_u` 各有 1/768 个有效元素超差。将设备的 BF16 QKV 投影代入同一标杆后，两处均与设备结果相同，所有有效元素的最大绝对差为 3.73×10⁻⁹。这 43 项按已核实的 FP32 点积累加顺序与 BF16 舍入差异记录。810 项的重复运行、状态别名、checkpoint 和未写区域检查均通过。另通过 ATK 精度 9/9、内存检测 3/3 和非法输入 10/10。

104 项扫描用例预热 3 次后取 5 次设备耗时中位数，较接入版均缩短。B40/N8/S4 的 BSH 从 298.486 µs 降至 173.443 µs，TH 从 300.226 µs 降至 176.103 µs。另用同卡、同输入交错测量 30 次，公开 ACLNN 从查询 workspace 到同步结束的中位数为 BSH 233.555 µs、TH 229.465 µs。

按架构分目录并合并 Host 后，Ascend 950 重新编译的设备二进制与上述 810 项验证使用的版本一致。合并构建另通过 20 项 B/N/S 与布局复验、5 项精度边界和 10 项非法输入测试。Atlas A3 已交叉编译。
