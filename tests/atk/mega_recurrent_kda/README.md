安装对应产品的 wheel 后从仓库根目录运行。A2 使用 `ascend910b`，A3 使用 `ascend910_93`，Ascend 950 使用 `ascend950`。


开发时，CPU 标杆的五项输出默认缓存在仓库的 `build/cpu-golden-cache`，可通过 `FLA_KDA_GOLDEN_CACHE` 指定复用目录。输入张量内容、布局、标量、标杆源码或 CPU 计算配置变化时重新计算。每次验证仍执行当前设备实现并比较输出。

九个用例覆盖 BSH、TH、不等长序列跨越 64 行、卷积权重的三种布局、物理状态槽间隙、缓冲区复用及 4096 token。CPU 与设备由相同种子生成输入，CPU 执行独立的 PyTorch 参考。设备调用公开 Stable ABI，检查四个状态输出与输入共用地址，以及 checkpoint 保持原值。

精度边界回归可另行运行 `python -m pytest -q tests/atk/mega_recurrent_kda/test_precision_boundaries.py`。用例覆盖单行 decay 投影、跨块卷积历史交接，整批 66 行但末组仅余 3 行时的 decay 计算，变长序列在非对齐位置切换分组、投影借用输出后的单行尾部，以及同一批次中长短序列共存的情况。

| 文件与分支 | case ID | 覆盖 |

### A2 INT8 随形状扩展的性能

N=6、S=4 的 TH 输入在 B=16 时，原有 QKV 暂存区能容纳所有 INT32 累加值。B=17 时，68 个 token 超过该区的容量，tiling 改用两段空闲空间，让 QKV 投影继续一轮完成。选择依据是空闲缓冲的大小、使用时机和 UB 容量。各形状的用户 workspace 增量均为 0 B。

| 形状与布局 | 单层原版 → 新版（µs） | 四层权重轮换原版 → 新版（µs/层） |
|---|---:|---:|
| TH，B=16、N=6、S=4 | 102.5 → 102.5 | 114.6 → 113.0 |
| TH，B=17、N=6、S=4 | 145.4 → 133.8 | 152.4 → 146.4 |
| TH，B=32、N=6、S=4 | 177.9 → 166.0 | 193.2 → 179.6 |
| BSH，B=17、N=6、S=4 | 144.5 → 130.7 | 149.3 → 137.1 |
| TH，B=8、N=6、S=16 | 202.3 → 185.9 | 209.6 → 190.9 |

两种构建在同卡交错运行，各测两轮。每轮预热 4 次后，单层取 9 次、四层轮换取 36 次完整融合 kernel 的中位数，再取两轮中位数。B=8、N=6、S=4 的模型输入继续走原有单轮路径。非模型输入的扫描覆盖 B=1–128、N=1–32、S=1–256 的采样点，另在 B=17、S=4 时改变 N，验证不同投影宽度的选路。
